一周大模型后训练入门计划：Tool Calling SFT + DPO 项目

项目目标：
训练一个小模型，让它根据用户问题稳定输出正确的 JSON 工具调用。
重点学习大模型后训练里的数据构造、SFT、DPO、自动评测和误差分析。

最终产出：

1. 一个可运行 GitHub 项目
2. 一份 SFT vs DPO 对比实验报告
3. 一个自动评测脚本
4. 一个 README，可用于简历或面试展示

推荐技术栈：
模型：Qwen 小模型，优先选择 0.5B / 0.6B / 1.5B 级别
训练方法：LoRA / QLoRA
训练阶段：SFT + DPO
框架：LLaMA-Factory 或 TRL
任务：中文 Tool Calling JSON 输出

工具设计：
定义 5 个工具即可：

1. search_docs
   用途：检索知识库
   参数：

* query

2. calculator
   用途：计算数学表达式
   参数：

* expression

3. query_order
   用途：查询订单状态
   参数：

* order_id

4. book_meeting
   用途：预约会议
   参数：

* date
* time
* topic

5. send_email
   用途：发送邮件
   参数：

* recipient
* subject
* content

模型输出格式统一为：

{
"tool": "工具名",
"arguments": {
"参数名": "参数值"
}
}

不需要调用工具时，输出：

{
"tool": "none",
"arguments": {}
}

Day 2：构造 SFT 数据

目标：
构造 500 到 1000 条 instruction 数据。

数据格式：

{
"instruction": "帮我查一下订单 A10293 的状态",
"input": "",
"output": "{"tool":"query_order","arguments":{"order_id":"A10293"}}"
}

数据类型要覆盖：

1. 单工具调用
   例如：
   “帮我查一下订单 A10293”

2. 不需要工具
   例如：
   “你是谁？”

3. 参数缺失，需要追问
   例如：
   “帮我预约个会议”
   输出：
   {
   "tool": "none",
   "arguments": {},
   "need_clarification": true,
   "question": "请提供会议日期、时间和主题。"
   }

4. 多种相似意图
   例如：
   “帮我算一下 123 * 456”
   “这个表达式 15 + 28 / 2 等于多少？”

5. 干扰问题
   例如：
   “帮我发邮件顺便查订单”
   先规定只允许单工具调用，选择最主要任务，或者输出需要澄清。

当天产出：

1. 至少 500 条 SFT 数据
2. 数据字段统一
3. 随机抽查 50 条，确保 output 是合法 JSON

Day 4：构造 DPO 偏好数据

目标：
构造 chosen / rejected 数据，让模型学会更偏好正确、简洁、合法的 JSON。

DPO 数据格式：

{
"prompt": "帮我查一下订单 A10293",
"chosen": "{"tool":"query_order","arguments":{"order_id":"A10293"}}",
"rejected": "{"tool":"search_docs","arguments":{"query":"订单 A10293"}}"
}

chosen 标准：

1. JSON 合法
2. 工具选择正确
3. 参数完整
4. 不输出多余解释
5. 不编造参数

rejected 类型：

1. JSON 格式错误
2. 工具选错
3. 参数缺失
4. 参数名错误
5. 输出了多余自然语言
6. 不该调用工具却调用了工具
7. 应该调用工具却输出 none

建议数量：
300 到 800 对 preference pairs。

当天产出：

1. DPO 数据集
2. rejected 错误类型统计
3. 更新 README 的数据构造说明
