# V1 实验总结报告

## 基本信息

- **项目**: 中文 Tool Calling 后训练（SFT + DPO）
- **基础模型**: Qwen2.5-0.5B-Instruct
- **V1 实验时间**: 2026-06-17
- **当前最佳模型**: SFT-v1

## 数据规模

| 数据集 | 数量 | 说明 |
|--------|------|------|
| SFT 训练数据 | 573 条 | 模板生成，覆盖 5 种场景 |
| DPO 偏好数据 | 760 对 | 程序化生成，10 种错误类型 |
| 评测集 | 50 条 | 标注数据，6 类场景 |

## 评测结果（50 条标注评测集）

### 整体指标

| 指标 | Base | SFT-v1 | DPO-v1 |
|------|------|--------|--------|
| JSON 合法率 | 82.0% | **100.0%** | 98.0% |
| 完全正确率 | 28.0% | **54.0%** | 42.0% |
| Bad Cases | 36 | **23** | 29 |

### 错误类型演变

| 错误类型 | Base | SFT-v1 | DPO-v1 | 趋势 |
|---------|------|--------|--------|------|
| JSON 格式错误 | 9 | **0** | 2 | SFT ✅ 消除，DPO ⚠️ 回退 |
| 该拒未拒 | 14 | 11 | **7** | 持续改善 |
| 不必要的追问 | 0 | 5 | **10** | SFT 引入 → DPO 加剧 |
| 该追问却调工具 | 5 | 5 | 7 | 始终未解决 |
| 参数值错误 | 5 | **2** | 3 | SFT 大幅改善 |

## 主要发现

### 发现 1：SFT-v1 是最佳模型
- JSON 合法率 82% → 100%（+18%）
- 完全正确率 28% → 54%（+26%）
- Bad Cases 36 → 23（-36%）

### 发现 2：DPO-v1 未稳定超过 SFT-v1
- 完全正确率从 54% 降至 42%（-12%）
- 改善了"该拒未拒"（14→7，-50%）
- 但引入了"过度追问"（0→10，新增 10 例）

### 发现 3：参数追问是三模型共同盲区
- 5 条参数缺失测试中，Base/SFT/DPO 全部为 0/5 正确
- 模型倾向于编造参数直接调用工具，而非追问用户

### 发现 4：SFT 是 JSON 稳定性提升的主要来源
- JSON 格式错误从 9 例降至 0 例
- 参数值错误从 5 例降至 2 例
- DPO 在此维度无额外增益

### 发现 5：4-bit 合并模型有精度损失
- 4-bit merge_and_unload() 后推理质量下降
- 推荐 float16 加载 base model + adapter 方式推理

## V1 局限

1. **评测集太小**（50 条）：无法支撑细分场景的稳定结论
2. **参数追问数据不足**（SFT 中仅占 7%）：无法教会模型追问
3. **DPO 数据分布偏差**：过度追问的 rejected 样例不足
4. **语义干扰未专门覆盖**：模型倾向于"看到关键词就调用工具"
5. **缺乏分场景指标**：只有整体准确率，难以定位具体问题

## V2 改进方向

1. 扩展评测集到 200+ 条，按场景分层
2. 将追问型 SFT 数据占比从 7% 提升至 20%+
3. 针对"过度追问"和"语义干扰"构造修复型数据
4. 升级评测脚本，增加分场景指标（过度追问率、不必要工具调用率）
5. DPO-v2 有条件执行：仅当 SFT-v2 超过 SFT-v1 后进行
