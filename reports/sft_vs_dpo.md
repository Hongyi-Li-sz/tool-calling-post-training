# SFT vs DPO 对比实验报告

## 实验概述

本实验旨在验证 **SFT（监督微调）和 DPO（偏好优化）两种后训练方法在小模型 Tool Calling 场景下的效果差异**。

- **基础模型**: Qwen2.5-0.5B-Instruct
- **任务**: 中文 Tool Calling JSON 输出
- **训练数据**: 573 条 SFT 数据 + 760 对 DPO 数据
- **评测集**: 50 条标注测试数据（6 类场景）

---

## 一、实验设计

### 1.1 两阶段训练流程

```
Phase 1: SFT（监督微调）
  目标: 教会模型"怎么做"
  数据: 573 条 instruction→output 对
  方法: QLoRA (rank=8), 8 epochs, lr=5e-5
  产出: SFT adapter (~17MB)

Phase 2: DPO（偏好优化）
  目标: 让模型"知道什么是好的"
  数据: 760 对 chosen/rejected
  方法: QLoRA (rank=8), 3 epochs, lr=5e-6, beta=0.1
  基线: SFT 模型（作为参考模型）
  产出: DPO adapter (~17MB)
```

### 1.2 评测指标

| 指标 | 计算方式 |
|------|---------|
| JSON 合法率 | `json.loads(response)` 成功比例 |
| 完全正确率 | tool 正确 + arguments 完整 + 行为匹配预期 |
| 错误分类 | 7 类错误自动标注 |

---

## 二、实验结果

### 2.1 整体对比

| 指标 | Base | SFT | SFT vs Base | DPO | DPO vs SFT |
|------|------|-----|-------------|-----|------------|
| JSON 合法率 | 82.0% | **100.0%** | +18% | 98.0% | -2% |
| 完全正确率 | 28.0% | **54.0%** | +26% | 42.0% | -12% |
| Bad Cases | 36 | **23** | -36% | 29 | +26% |

### 2.2 分场景分析

#### 单工具调用（19 条）

| 模型 | 完全正确 | 主要错误 |
|------|---------|---------|
| Base | 9/19 (47%) | JSON 格式错、工具选错 |
| SFT | **16/19 (84%)** | 参数值轻微偏差 |
| DPO | 14/19 (74%) | 参数值偏差、JSON 偶发回退 |

**结论**: SFT 大幅改善工具调用能力。DPO 有轻微回退。

#### 拒调用（15 条）

| 模型 | 完全正确 | 主要错误 |
|------|---------|---------|
| Base | 1/15 (7%) | 几乎全部输出自然语言 |
| SFT | 6/15 (40%) | 不必要的追问 ×5，误解调用 ×4 |
| DPO | **8/15 (53%)** | 不必要的追问 ×7，误解调用 ×0 |

**结论**: DPO 在此场景表现最好，完全消除了"不该调却调工具"的错误。但"过度追问"增加了。

#### 参数追问（5 条）

| 模型 | 完全正确 |
|------|---------|
| Base | 0/5 (0%) |
| SFT | 0/5 (0%) |
| DPO | 0/5 (0%) |

**结论**: 三模型全部失败。模型无法在参数不足时主动追问。这是当前最严重的功能缺陷。

### 2.3 错误类型迁移分析

```
                    Base → SFT              SFT → DPO
                  ─────────────          ─────────────
JSON 格式错误      9 → 0    ✅ 消除       0 → 2    ⚠️ 回退
该拒未拒          14 → 11   ⬇ 改善       11 → 7   ✅ 持续改善
参数值错误          5 → 2    ✅ 大幅改善    2 → 3    ➡ 持平
该追问却调工具      5 → 5    ➡ 未变        5 → 7    ⚠️ 略恶化
不必要的追问        0 → 5    ⚠️ 新问题     5 → 10   ❌ 加剧
```

## 三、DPO 训练质量分析

### 3.1 DPO 训练指标

```
rewards/chosen:    -0.27    ← 模型给 chosen 的奖励
rewards/rejected:  -4.81    ← 模型给 rejected 的奖励  
rewards/margin:     4.55    ← 奖励差值（越大越好）
rewards/accuracy:   1.00    ← chosen 被偏好的比例
```

reward/margin = 4.55 表明模型已经**强烈偏好正确输出**。accuracy = 1.0 说明在训练集上 **100% 偏好 chosen**。

### 3.2 训练充分但有副作用

DPO 在训练集上表现极好（对 chosen 的偏好远强于 rejected），但在评测集上出现了两个副作用：

1. **"不该调工具却调"的改善**（14→7）— 正面效果 ✅
2. **"不必要的追问"的加剧**（5→10）— 负面效果 ❌

这反映出 **DPO 数据中"追问型 rejected"比例不足**，导致模型对追问行为的惩罚不够。

---

## 四、关键发现

### 发现 1：SFT 是当前最佳选择

SFT 在 50 条评测集上完全正确率 54%，比 DPO 高 12 个百分点。**对于小模型 Tool Calling 场景，SFT 比 DPO 更直接有效。**

### 发现 2：DPO 需要更高质量的数据

DPO 的副作用（过度追问）源于偏好数据的分布偏差。DPO 数据中应该有更多"不该追问却追问了"的 rejected 样例。

### 发现 3：参数追问是最难的问题

三模型在 5 条参数缺失测试上全部失败。模型倾向于"做点什么"而非"说我不知道"。**这需要从数据层面根本性增加追问类样本比例。**

### 发现 4：QLoRA 合并模型有精度损失

4-bit 量化模型 `merge_and_unload()` 后推理质量下降。**推理时推荐 float16 加载 base model + adapter。**

---

## 五、优化路线图

### 短期（当前迭代）

1. **扩充澄清型数据**: SFT 数据中追问类从 7% 提升至 20%+
2. **DPO 数据纠偏**: 增加"不必要追问"的 rejected 样例
3. **迭代训练**: re-SFT → re-DPO

### 中期

4. **多轮对话**: 支持参数逐轮补全
5. **更大模型**: 尝试 Qwen2.5-1.5B 做对比实验
6. **GPT-4 Judge**: 引入语义级自动评测

### 长期

7. **多工具并行调用**: 单次输出多个工具调用
8. **RAG 工具集成**: 接入真实检索系统

---

## 六、结论

本实验验证了 SFT + DPO 在小模型 Tool Calling 场景下的有效性：

- **SFT 提升显著且稳定**: JSON 合法率 82%→100%，完全正确率 28%→54%
- **DPO 有效但需精细调参**: 改善了拒调用但引入了过度追问
- **后训练的上限受限于数据和模型规模**: 0.5B 模型的语义理解能力是硬上限

**SFT 模型推荐用于展示和生产原型**。DPO 方向正确，需要更好的偏好数据才能发挥全部潜力。
